Armazenamento embutido

Usar um armazenamento embutido significa aproveitar um banco de dados que roda dentro do cluster Kubernetes, tipicamente como um serviço conteinerizado, por exemplo, etcd. Essa opção simplifica a implantação e pode melhorar o desempenho e a segurança. A alternativa é bancos de dados externos.

Opções de armazenamento

Experimental

O RKE2 suporta oficialmente o etcd embutido, o SQLite embutido é considerado experimental.

  • Embutido etcd: O etcd embutido é o armazenamento padrão e será usado se nenhuma outra configuração de armazenamento estiver presente.

  • Embutido SQLite: O SQLite não pode ser usado em clusters com múltiplos servidores. Ele usa o projeto kine.

etcd Embutido

O etcd embutido é o armazenamento padrão e será usado se nenhuma outra configuração de armazenamento estiver presente. É a única opção embutida que permite implantar o RKE2 em modo HA. A menos que o parâmetro seja explicitamente removido, um pod etcd será implantado por servidor RKE2 e todas as instâncias etcd manterão um quórum. O RKE2 inclui ferramentas para criar facilmente instantâneos ao usar este armazenamento, conforme explicado nas instruções de Backup e Restauração.

SQLite embutido

Esta opção embutida não é recomendada para produção, mas pode ser útil se você precisar rodar um cluster simples e de curta duração, por exemplo, em um ambiente de CI/CD. O modo HA não é suportado ao implantar com SQLite.

Servidor Único com SQLite

  1. Defina disable-etcd sem o parâmetro server no arquivo de configuração.

    disable-etcd: true

  2. Install RKE2.

    curl -sfL https://get.rke2.io | sh -

  3. Ative o serviço rke2-server.

    systemctl enable rke2-server.service

  4. Inicie o serviço rke2-server.

    systemctl start rke2-server.service

Você pode acompanhar o início do servidor por kubectl get nodes para ver o servidor obter o status Ready. Veja Acesso ao cluster para mais informações sobre como acessar o RKE2.
